# 在多台电脑间同步

Anubis 没有自己的账号或服务器。它把你的内容保存在浏览器的同步存储中，由浏览器复制到你的其他电脑上。若要在 Firefox 和 Chrome 之间也能共享，你可以连接自己的存储服务。

## 同步的内容

- **你的列表**：你排过名或加过标签的每个网站
- **设置**
- **标签选择**：每个标签的作用，以及它的名称和颜色
- **订阅**：你订阅了哪些列表

你订阅的列表本身不会在电脑之间复制。每台电脑会从同一个地址下载自己的副本。

## 浏览器同步

这一功能默认就是开启的，在 Anubis 中无需任何设置。不过，Anubis 无法得知你浏览器的同步是否已开启。如果某项更改没有出现在你的另一台电脑上，请在两台电脑上都检查这些设置。

- **Firefox：** 用你的 Mozilla 账号登录 Firefox。在 Firefox 的设置中，**同步**下，确保勾选了**附加组件**：这也会同步附加组件的数据。Firefox 大约每 10 分钟同步一次。若要立即同步，请在同一位置选择**立即同步**。
- **Chrome：** 登录 Chrome 并开启同步，同时让**扩展程序**保留在它同步的内容中（Chrome 的设置，**你和 Google** 下）。

浏览器同步只能到达你其他电脑上的同一种浏览器。Firefox 和 Chrome 之间不互相同步，Android 版 Firefox 则完全不同步附加组件的数据。

## 在浏览器之间

若要在 Firefox 和 Chrome 之间，或与 Android 版 Firefox 共享，请在每个浏览器中连接同一个存储。这是可选的，在你连接之前什么都不会改变。Anubis 可用于任何提供 **WebDAV** 的存储服务，这是应用在那里保存文件的一种标准方式。它会在那里保留一个文件，`anubis-sync.json`。

### 获取地址和密码

你需要从服务中得到三样东西：它的 WebDAV 地址、你的用户名，以及一个应用专用密码。大多数服务在这里不接受你平常的密码。它们会让你为每个应用另建一个密码，你可以收回它，而无需更改自己的密码。

| 服务 | 地址 | 密码 |
| --- | --- | --- |
| **Koofr**（免费 10 GB） | `https://app.koofr.net/dav/Koofr` | 在 Koofr 中，**Preferences → Password → App passwords**：创建一个。你的用户名是你的电子邮件地址。 |
| **InfiniCLOUD**（免费 20 GB） | 开启后，显示在你的账号页面的 **Apps Connection** 下 | 同一页面会显示应用专用的用户名和密码。 |
| **Nextcloud** | `https://your-server/remote.php/dav/files/your-user-name/` | **Settings → Security → Devices & sessions**：创建一个应用密码。 |

其他服务和你自己的服务器也可以，只要它们提供基于 `https://` 的 WebDAV。任何文件夹都可以：给出它的地址，Anubis 就会把文件放在那里。以 `.json` 结尾的地址会被直接当作文件本身使用。

### 连接

![设置，同步](../../img/options-sync.png)

1. 打开**设置 → 同步**，在**在浏览器之间**下输入地址、你的用户名和密码。
2. 保持**对同步文件进行端到端加密**开启，并选择一个至少 12 个字符、长而独一无二的密码短语。在每个浏览器中使用相同的密码短语。Anubis 会把它保存在该浏览器的本地扩展存储中，以便后台同步能够运行；它绝不会被发送到服务器，也不会被浏览器同步复制。不要使用你的 WebDAV 登录密码。
3. 点击**连接**。浏览器会询问是否允许 Anubis 访问该服务器。Firefox 还会询问 Anubis 是否可以把你的列表发送到那里。
4. 在你的另一个浏览器中，用相同的加密密码短语做同样的操作。

之后，**设置 → 同步**会显示 Anubis 上次同步的时间，或出了什么问题。**立即同步**会立刻同步。

### 为什么采用这种加密

Anubis 使用 **AES-256-GCM**，这是一种得到广泛支持的认证加密模式，内置于浏览器的 Web Crypto API 中。AES 对同步文件加密；GCM 还会检查密文是否被改动，并且每次写入都使用新的随机 nonce。256 位的密钥是用 **PBKDF2-SHA-256** 和一个随机盐值，由你的密码短语派生出来的，所以 Anubis 不会发送或存储单独的密钥文件。使用浏览器内置的加密功能，避免了附带第三方加密库。

这保护的是文件的内容，而不是你连接服务器这一事实。服务器运营者仍然可以看到连接的元数据，也可以删除或替换文件；加密无法阻止对方扣留或重放较旧的加密副本。如果你忘记了密码短语，服务器上的副本将无法恢复；你在每个浏览器中的数据仍然可用。请选择一个长而独一无二的密码短语，并另外保留一份备份。

Anubis 会把密码短语保存在该浏览器的本地扩展存储中，以便自动同步。它无法抵御能访问你的浏览器配置文件或以你的身份运行代码的人。WebDAV 凭据也会保存在本地，并发送到服务器用于登录。

### 更改密码短语

在**设置 → 同步**中，使用**更改加密密码短语**。输入并确认一个至少 12 个字符的新密码短语。Anubis 会先检查当前的密码短语能否解密服务器上的文件，然后只有在服务器确认期间没有人改动过它时，才会替换它。如果这项检查或写入失败，Anubis 会保留当前的密码短语，并且不会覆盖文件。如果文件在操作期间发生了变化，请先同步，再重试。

如果服务器保存新文件时连接断开，Anubis 会把文件读回来。当新的密码短语能打开它时，Anubis 就保存新的密码短语。当 Anubis 无法连接服务器进行检查时，它会保留旧的密码短语并告诉你。如果下一次同步随后报告密码短语错误，请输入新的密码短语。

更改成功后，请在同步之前，在其他每个浏览器中输入新的密码短语。仍在使用旧密码短语的浏览器无法读取或更改加密文件；它会报告密码短语错误，并且不会动该文件。

新建的连接默认使用加密。若要关闭，请在连接时取消勾选该选项；这样服务器运营者就能读取该文件。已有的连接在你于“设置 → 同步”中输入并确认密码短语并选择**保存密码短语并同步**之前，会保持不加密。加密的文件要求每个浏览器都有密码短语；如果缺少或错误，Anubis 不会覆盖它。从设置中导出的普通备份不会被这项功能加密。

### 何时同步

- 你更改某些内容几秒钟之后
- 浏览器启动时
- 你搜索时，最多每 5 分钟一次

### 来自两个浏览器的更改

Anubis 会合并每个浏览器的更改，所以同时使用两个浏览器时不会丢失任何内容：

- 你在 Firefox 中隐藏的网站和在 Chrome 中加了标签的网站，都会保留。
- 如果你在一个浏览器中提升了某个网站，又在另一个浏览器中为它加了标签，它最终会既被提升又带有标签。
- 如果两个浏览器在同步之前更改了同一项内容，比如同一个网站的排名或同一项设置，则最后同步的浏览器胜出。

浏览器第一次连接时，会从文件中获取所有内容。你在该浏览器中连接之前更改过的网站和设置也会保留，除非文件更改的正是这些项目。

### 断开连接

**设置 → 同步**中的**断开连接**会停止该浏览器中的同步。你的列表和设置会留在浏览器中，文件会留在服务器上。如果想删除它，请在服务器上删除该文件。

## 限制

- **大小：** 浏览器同步为每个附加组件提供约 100 KB 的空间。Anubis 在保存前会压缩你的列表，所以大约能容纳 10,000 个网站。**设置 → 同步**会显示它们占了多少空间。如果你的列表超出了这个范围，浏览器同步只会把它保留在那台电脑上，设置中也会这样说明；设置、标签选择和订阅仍会同步。通过服务器同步没有这样的限制。
- **来自其他主机的列表：** 如果你订阅了不在 GitHub 上的列表，每个浏览器都会请求下载它的权限。同步之后，请在另一个浏览器的**设置 → 列表**中点击该列表的**立即更新**按钮（↻），以便在那里允许。
- **只迁移一次：** 你也可以[导出备份](./import-and-backup.md)，然后在另一个浏览器中恢复。同步文件的格式相同，所以**恢复备份**也能读取它。

## 隐私

浏览器同步通过你的浏览器账号进行，就像你的书签一样。Anubis 从不会看到它。

当你连接服务器时，你的列表、设置、标签选择和订阅只会发送到该服务器，而不会发往其他任何地方。启用端到端加密后，服务器无法读取同步文件；不启用时，服务器运营者可以读取。你的 WebDAV 用户名和密码会保存在该浏览器中，发送到服务器用于登录，并且绝不会放入浏览器同步或同步文件。加密密码短语会保存在你设置它的每个浏览器的本地，并且绝不会发送到服务器。参见[隐私与权限](./privacy.md)。
